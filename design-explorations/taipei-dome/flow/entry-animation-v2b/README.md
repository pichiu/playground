## 展示假設

離座為藍 9→1、白 1→9；進場為大隊 1→9。三條藍衣樓梯列鏈固定，139、140左、140右各用自己的排內走道。斜切在到達集結前進行。下一藍隊以先隊三路尾端通過共用斜切段的示意時刻接續，不要求全隊站定。

動畫以固定圖面速度、同列的走道／斜切／集結節點順序、門口 gateIdx 排序產生節奏。集結與進場分成兩階段以便檢圖，未對全部路口建立互斥或身體佔用約束。不同版本各自正規化，不能用進度、等待量或播放長度比較效率。

來源為 2026-10-19 完整草案與原版 2 的 4ad7e40，原版保持不變。白2樓梯集結、B1匯流、藍1反向進6口、跨衣色會合與現場寬度仍待解。

## 驗證範圍

檢查兩版人員與座位唯一、原場內定位一致、路徑端點與時間順序。Node VM 搭配 Canvas 跑過 1,356 個繪圖狀態（A/E、兩版、對照、全大隊、衣色和路段）。環境沒有可啟動的瀏覽器，未做實際瀏覽器的版面與觸控驗證。這些是頁面與資料檢查，不是動線無碰撞認證。

## 白衣 1→9 接續複核（10/19 補充）

入口 `redesign/white-review.html` 預設白1，勾選疊看後兩隊，可切離座→集結／集結→6口／6口→定位，三色代表固定 A/B/C 路，虛線代表後兩隊，金圈標跨隊交點樣本。E頁亦支援 `?color=white&k=1`。`white-review.json` 保存各白隊、相鄰白隊及1→3的幾何證據。

複核發現 B1 來源出口未對白衣套用有序三路限制；不同列共用一個出口、出口次序反轉、跨出口拆列均造成橫切。各隊 departure=0 不代表跨隊 arrival 沒有交點。白2的97人樓梯候隊尚無容量依據；候選控制改法為留在自有休息區或已確認候隊區，再依前隊三路隊尾通過相關路段逐段放行。此控制尚未改寫現行動畫排程，也不能消除既有幾何交叉。

修訂座位與集結應聯動，不能只交換白1而把多餘座位塞給白2/3：須約束白 A=1→7→13…49、B=2→8→14…50、C=3→9→15…51，來源出口與主走道三路的實體順序一致。同出口只能同路接續；改接其他出口必須驗證合流點。白8/9原集結位置的來源限制只允許144M/145，不能宣稱已提供三個獨立出口，須重排集結位置或控制上游接續。

跨隊稽核只計同樓層、線段內部1%–99%、交角 sin≥0.2 的橫切；`uniqueGeometricPoints` 去重座標、`uniquePersonPairs` 去重人對，兩者不同。站定點檢查僅白1/2/3、0.03圖面單位，未涵蓋人體寬度或隊列占地。
