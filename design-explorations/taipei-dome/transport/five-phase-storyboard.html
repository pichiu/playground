      重新設計對應說明

      P0 五階段流程
      舊版把「登記」「排車」「點名」揉在單一頁面的兩種模式;新版依真實時間順序拆成五個畫面(①登記 → ②調車 → ③配額 → ④排人 → ⑤點名), 每個畫面只服務一種角色、一個當下能做的動作,順序即是流程本身。
      P0 兩層調度(合心/聯區)
      合心交通‧合心活動決定「有幾台車、怎麼跑」(②調車/路線);聯區活動決定「每台車給哪些和氣多少名額」(③配額)。 兩層職責分開,避免舊版把「建車」與「配人」揉在一起,誤讓和氣自建車次或看不到全局座位分配。
      P1 路線車多停靠(bus_stops)
      新增路線車能力:一台車可以「沿路載」多個上車點(如第四車:崇明路口 → 安平聯絡處 → 十期重劃區)。 資料模型新增 bus_stops(busId · 上車點 · 順序 seq · 各站時間);一站 = 點對點車,多站 = 路線車。
      P1 以車為主排人(非批次)
      ④排人上車拿掉「批次/多選/指派」語彙,改成 BUS-FIRST:先選車,畫面固定顯示「安平和氣 → 第一車」這個目標, 再從「加人」清單逐一把人加進這台車:具體語言取代抽象的批次操作,目標全程可見不怕選錯車。
      P0 樂觀點名
      ⑤點名的上車 toggle 點下立即翻成「已上車」,不等伺服器回應;個別列可顯示「同步中…」小字,但不鎖住整張車卡, 點名節奏不被網路延遲打斷(延續前版決策)。
      P1 thumb-zone
      ⑤點名的主要動作(加人 / 本車點名完成)收斂到畫面底部固定列,對齊單手持機時姆指自然可及的範圍(延續前版決策)。
      P0 彙總無人名
      ②調車、③配額兩個「調度頁」畫面只顯示依上車點或依和氣的計數,不顯示任何人名;個人姓名只出現在①登記、④排人、⑤點名這三個 「和氣/現場」畫面,對應 PII 分層鐵律(調度角色不需要、也看不到具體是誰)。
      配額驗證
      每台車的配額合計即時與座位數比對:符合顯示 ✓(ok 綠色),超出顯示 ⚠ 超出(warn 琥珀色); 數字統一提升到 --ink 權重,確保操作時第一眼就能讀到判斷依據。
      開放問題
      留給 spec 續寫:bus_stops 的順序/時間是否允許聯區事後微調?路線車的配額要不要拆到「站」層級(而非整車一個配額), 還是維持「和氣配額 + 個人登記時的上車點」兩欄位即可推導?回程是否重用同一組 bus_stops (順序反轉、時間另填),或需要另建一筆反向路線?見 docs/superpowers/specs/。
