# 入經藏進場動線 版本 3：兩路直進

日期：2026-10-22 · 狀態：設計定稿，待建造 · 位置：`design-explorations/taipei-dome/flow/entry-animation-v3/`

## 1. 目的與緣由

2c（`flow/entry-animation/`，設計見 `2026-10-19-entry-plan-2c-design.md`）讓藍衣先全部下 B2 集結、白 1–3 在 P1／樓梯／B1 候隊，再依大隊 1→9 由西一入口六路進場。它能跑，但規則長、集結區多（7 處）、死巷要整塊遞補，1,072 人要停下來等，最久約 222 秒。

版本 3 試另一個方向：**兩路就好，不集結**。白衣一路、藍衣一路，照大隊 1→9 直接離座、走 B1 走廊、下樓梯，到 B2 後各自散成三條、由西一入口六路進場。每個人離座後一路走到場內，不停。

代價已經和企劃確認接受（見 10/21 的說明頁 https://claude.ai/artifact/7qp6PF6obg8579pPr5mLVs）：

- 全長約 363 秒（2c 260.5 秒）。樓梯每 0.4 秒只過 2 人。
- 一列可能分坐兩個出口：大隊不拆的排法座位不夠（所有組合都排不進去，最接近仍差 51 席），所以**出口坐滿就換下一個，換口點可以落在大隊中間**。
- 沒有緩衝區；出口幹部照名單、照時間放人。

2c 保持原樣、不改、不刪；版本 3 是平行的另一個成品，兩者並存以便對照。

## 2. 目標、非目標、反目標

目標
- 一個新資料夾 `entry-animation-v3/`：一份 `data.json`、七個頁面、`seats.csv`、可重算的 `build/`，結構與 2c 相同。
- 走廊、樓梯、B2 到西一入口全程不交叉：任何時刻白衣（A 路）用的出口比藍衣（B 路）近，且兩路出口在不同階梯。
- 沒有人在出口之後停下來等（`t.assembly == t.enter`，沒有 `adv`）。
- 可被程式驗收：碰撞 0、巢狀 0、樓梯兩路與西一入口六路不斷拍、座位唯一、出口只在坐滿時換。

非目標
- 不改 2c 的任何檔案（例外：首頁加一張 v3 卡、2c README 加一行指向 v3，見 6.8）。
- 不改場地幾何、座位、走道口、樓梯 L 形、西一入口、場內路徑：全部沿用 2c 的 `base.json` 與 `routes.Geometry`。
- 不改時間常數（步速 1.1、節拍 0.4、錯開 0.17、T0 6.73、大隊空檔 0.8）。若有人要更快，那是另一個版本。
- 不做現場秒數或通道容量認證（同 2c）。

反目標（做到也算失敗）
- 為了過碰撞檢查而改出口順序、路別或欄內順序。碰撞只能用個人時間線平移（≤ 0.15 秒）解；解不掉就停下來回報，不出貨。
- 讓任何人在出口之後站著等（為了避撞而延後離座可以，延後是在座位上）。
- 改到 `flow/entry-animation/`（2c）的頁面、資料或建置。
- 任何頁面在 375px 寬出現橫向捲動或疊字。

## 3. 規則

### 3.1 兩路與欄內順序

- 路 A＝白衣，B1 走廊偏移 **+0.12**（靠看台側）；路 B＝藍衣，偏移 **−0.12**。樓梯、B2 平台沿用 2c 的 `miter` 斜接折線，偏移相同。
- 樓梯序：大隊 1→9。每個大隊，A 路是白衣三列（列 6k−5、6k−4、6k−3，即西一入口 j = 0、1、2），B 路是藍衣三列（列 6k−2、6k−1、6k，j = 3、4、5）。兩路同時走。
- 每一路裡三列**交錯排隊**：每列先依排號由大到小排好（排大的先，與 2c 西一入口順序相同），再輪流取：j 小的那列先，一輪取三列各一人；某列取完就跳過，其餘照輪。例：白衣大隊 1 是 j0 第 1 位、j1 第 1 位、j2 第 1 位、j0 第 2 位……
- `laneIdx`：該路從大隊 1 第一位起的序號（0 起算），全路連續。
- `gateLane = (lie − 1) mod 6`、`gateIdx`（同一條西一入口線依大隊、排大的先）與 2c 相同。

為什麼 A 是白衣：A 在 B1 靠看台側，下樓轉兩次彎後在 B2 是靠場側；從樓梯走向西一入口時，最先碰到的是 j=0（最靠場側、最靠樓梯）那條進場線。白衣是 j=0–2，到 j=2 就全部轉進場；藍衣往前到 j=3–5 時已經沒有白衣，所以兩路不交叉。這與 2c 的 `_b2_to_gate` 幾何一致（j 的 B2 偏移 0.2 − 0.08j）。

### 3.2 出口與指派

出口、可用席、走道口與接入點完全沿用 2c（`plan.EXIT_DEF`、`usable_seats`、`approach`）：139 206、140 291、141 259、142 255、143 185、144 198、145 273，合計 1,667。

每路依序使用的出口（固定，不搜尋）：

| 路 | 出口順序 |
|---|---|
| A（白） | 139 → 140 → 141 → 142 |
| B（藍） | 142 → 143 → 144 → 145 |

**出口坐滿就換**：依 `laneIdx` 往下填，目前的出口沒有空席才換下一個。142 兩路共用：A 路需要的 142 席數 = A 總人數 − (139+140+141 可用席)（目前 809 − 756 = 53），先保留給 A；B 路在 142 可用的是其餘（202）。算出來任何一路不夠就 `SystemExit` 並印出差多少。

預期結果（10/21 模型）：A：139 206、140 291、141 259、142 53；B：142 202、143 185、144 198、145 215；空位 58 席全在 145。換口點 6 個，各落在某大隊中間，共 18 列分坐兩個出口（2c 稱為「拆欄」，版本 3 允許）。

性質（`check.py` 驗，不得退讓）：
1. 每路沿 `laneIdx` 出口序不遞減（只往上游換）。
2. 每路除最後一個出口外，換口前那個出口已用滿可用席（142 以兩路合計算）。
3. **依時間的巢狀**：把兩路依實際通過樓梯口的時刻合併；任何時刻 A 目前的出口 rank < B 目前的出口 rank，且兩者在不同階梯（`plan.STAIR_OF`：139/140 同一座、144/145 同一座）。只有一路已經開始時不比較。

### 3.3 出口內的座位

同 2c 3.4：每個出口一條 FIFO，由上排往下、每排由出口側往中央（139、144 由大號往小號，其餘由 1 號起），跳過 blocked/work 與 139 的 1–5 號。FIFO 的順序依**計畫的樓梯時刻**（兩路共用一個出口時才有差別，例如 142：藍衣大隊 1–3 先走、坐上排；白衣大隊 9 最後走、坐下排）。`exitSeq` 是這條 FIFO 的序號。

### 3.4 時間：一個時鐘

常數同 2c：V = 1.1、HEADWAY = 0.4、STAGGER = 0.17、T0 = 6.73、DADUI_GAP = 0.8。

- 樓梯口時刻 S（通過 B1 樓梯口 u 13.15）：路 L 在大隊 k 的第 n 位，S = T_S0 + T_k + 0.4·n + 0.17·(A=0, B=1)。
- 大隊交界兩路對齊：T_1 = 0；T_{k+1} = max(兩路大隊 k 最後一拍，含錯開) + 0.4 + 0.8。對齊的理由同 2c（兩路人數不同，短的那路不提早帶下一大隊出來）；0.8 秒空檔讓前一大隊隊尾先過西一入口線的轉入點。
- 離座 = S − 座位到樓梯口的路程 / V；過西一入口 = S + 樓梯口到西一入口收攏點的路程 / V；之後沿版本 1 場內路徑等速重算（同 2c `person_path` 的 post 段）。
- T_S0 取讓最早離座者剛好在 T0 離座的最小值。
- `t.assembly = t.enter = S`（沿用 2c FEEDER 的語意：沒有集結）。`t.stairPlan` 不輸出。

### 3.5 路線

每個人都走 2c 的 FEEDER 路線（`Geometry.arrival_route` 的 FEEDER 分支）：座位 → 走道口 → 走廊邊 → 斜向前方 0.3 併入自己那一路 → 沿 B1 到樓梯口前 0.25 → 下樓梯（`_down_stair`）→ B2（`_b2_to_gate(j)`：從 B2 起點側移到 j 的偏移、到西一入口收攏點）。`LANE_OFF` 改為 `{'A': 0.12, 'B': -0.12}`。不建 ZONES、STAIR_SLOTS、P6、死巷、遞補；`routes.py` 只留這條路線需要的部分。

### 3.6 碰撞

同 2c：`collide.py` 全程（0.01 秒、半徑 0.03），穿過站定者與走路互撞都必須 0。處理手段只有一種：把後到的那位整條時間線延後 0.05 秒一步，累計 ≤ 0.15 秒（2c `avoid`）。解不掉就停下來回報，不出貨，也不改規則。

## 4. 檢核（`meta.checks`，總覽頁顯示）

全部由 `persons`／`restSeats` 重算；`exits` 的 `used/capacity/order` 只拿來比對。

| 鍵 | 項目 | 門檻 |
|---|---|---|
| `collisions` | 穿過站定者 / 走路互撞 | 0 / 0 |
| `nesting` | 依時間的巢狀（3.2 性質 3）：違反時刻數、同階梯時刻數 | 0 / 0 |
| `assignment` | 換口往下游次數 / 未坐滿就換的次數 / 每路段數 / 分坐兩出口的列數（資訊，不算違反） | 0 / 0 / A 4 段、B 4 段 / 列出 |
| `routes` | 每大隊六列頭一位（各列 `gateIdx` 最小者）的路徑，從進 B2（B2 走廊 u ≥ 0.9）到過西一入口後 3 秒，兩兩不相交；另外 A、B 兩路頭一位從 B1 接入到樓梯口不相交 | 0 |
| `continuity` | 樓梯口兩路（依 `laneIdx`、以 `t.enter`）：大隊內拍距 0.25–0.55、大隊交界 ≤ 7 秒（見下）、順序單調；西一入口六路（依 `gateIdx`、以 `t.gate`）：拍距 ≥ 0.25、順序單調、大隊內拍距 ≤ 1.4（三列交錯 1.2 + 避撞平移） | 成立 |
| `noWait` | 沒有人站著等：每人 `assembly == enter`、沒有 `adv`、`path` 從離座到到位時刻嚴格遞增（相鄰點停留 ≤ 0.01 秒） | 違反 0 |
| `seats` | 同 2c（唯一、合法、區＝出口、FIFO 順序、`exits[].order` 名單＝該出口全員） | 同 2c |
| `capacity` | 同 2c | 同 2c |

不再有 2c 的 `staging`、`advance`。

大隊交界門檻（建造者的判斷，10/22）：2c 用 5 秒，因為那時一欄一路、各欄人數差 ≤ 6 人。版本 3 一路三列，同一大隊兩路人數差到 12 人（大隊 1 白 87、藍 99），依 3.4 的對齊規則，短的那路在交界會空約 6.2 秒（大隊 8 約 5.2 秒）。這是兩路人數不等的必然，與 2c 3.6 說的「較短的路在交界有空檔，不是斷拍」同一回事。門檻因此放到 7 秒，並另驗：每個交界的空檔 = 0.4 ×（兩路該大隊人數差）+ 0.4 + 0.8 ± 0.4（錯開與避撞平移），不得更大。

## 7. 建置

```
cd entry-animation-v3/build
python3 plan.py  base.json plan.json
python3 build.py base.json plan.json ../data.json ../seats.csv
python3 check.py ../data.json
python3 -m pytest tests -q
```

`base.json`、`geo.py`、`collide.py` 原樣複製；`plan.py`、`routes.py`、`build.py`、`check.py` 以 2c 為底改寫（刪掉集結相關）。`tests/` 以 2c 為底：規則、座位、時鐘、檢核（含竄改偵測）、七頁 Playwright、追蹤檔與管線輸出逐位元相同。`build/README.md`、資料夾 `README.md` 照版本 3 寫。

## 9. 假設與風險

- 換口點只看容量；若某出口實際可用席不同，換口點會移動，規則不變。
- 兩路交錯讓同一條西一入口線間隔約 1.2 秒，某列先排完時其餘兩列間隔會縮到 0.8、0.4 秒，屬正常。
- 10/21 的模型估算沒跑碰撞；B2 起點兩路各自側移到三條線的那一段（+0.12 → +0.2/+0.12/+0.04、−0.12 → −0.04/−0.12/−0.2）是唯一新的幾何組合，若 `collide.py` 在這裡報錯而平移解不掉，停下來回報，不改幾何。
