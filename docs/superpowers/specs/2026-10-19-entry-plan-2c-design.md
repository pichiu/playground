# 入經藏進場動線 2c：單一成品設計

日期：2026-10-19 · 狀態：設計定稿，待建造 · 位置：`design-explorations/taipei-dome/flow/entry-animation/`

## 1. 目的

西一＋桃竹 1,609 人（9 大隊 × 6 列，每大隊 3 列白衣、3 列藍衣）要從 B1 看台 139–145 區的休息區離座，走 B1 走廊、下只有三路寬的樓梯到 B2，分別集結後由 6口 依大隊 1→9 六路進場，到場內身分證位置。

之前的四個版本（版本 1、版本 2、2a、2b）各自一個資料夾、各自一份資料、各頁有版本切換。這次只留一個版本：**2c**。它的休息區座位用一條規則排出（第 3 節），並以 redesign 的「依讀者拆頁」為骨架重組成一個產品：一個資料夾、一份 `data.json`、一個總覽入口、六個看法頁。

## 2. 目標、非目標、反目標

目標
- 走廊、樓梯、B2 到 6口 全程不交叉：每個時刻三路的供應出口維持「近的供內側、遠的供外側」。
- 每個大隊的三欄各自來自單一出口；每一路只換兩次出口，且每次都換到更上游的出口。
- 每個休息區出口是一條 FIFO：由上排往下、由出口側往中央，先走的坐上面。
- 一份可被程式驗收的資料：碰撞檢查、逐序號巢狀、進場後每路不斷拍、座位唯一。
- 六個看法頁都只讀同一份 `data.json`；首頁只留一張卡。

非目標
- 不做現場秒數或通道容量認證。時間單位沿用版本 1／2 的動畫節奏（1 單位 ≈ 7.6 m，步速 1.1 單位/秒），只保證相對關係。
- 不重新設計場內（6口 之後）的路徑與定位：沿用版本 1 的場內幾何，只重新計時。
- 不產生 Excel（版本 2 的 `excel.py` 依賴 repo 外的 10/17 範本）。座位表以 `seats.csv` 為準。
- 不保留版本切換、「對照」功能，也不保留舊的單頁動畫。

反目標（做到也算失敗）
- 為了過碰撞檢查而改動座位指派或路別指派。碰撞只能用個人離座時刻、走道口停等來解；解不掉就回報，不改規則。
- 為了湊人數而拆欄（一欄來自兩個出口）。
- 任何頁面在手機寬度（375px）出現橫向捲動或疊字。

## 3. 排位規則（已決定）

### 3.1 樓梯序與路別

樓梯三路由北到南為 A、B、C；A 最靠看台側（B1 走廊上偏移 +0.12 單位），B 中間（0），C 最外側（−0.12）。樓梯上依序通過 18 個區塊：**藍9、藍8、…、藍1、白1、白2、…、白9**。每個區塊三欄，一欄一路：

| 衣色 | 路 A | 路 B | 路 C |
|---|---|---|---|
| 白 k | 列 6k−5 | 列 6k−4 | 列 6k−3 |
| 藍 1 | 列 4（6k−2） | 列 5 | 列 6 |
| 藍 k（k = 2…9） | 列 6k | 列 6k−1 | 列 6k−2 |

6口 六路由北數 j = 0…5 = 列號 (lie−1) mod 6，與版本 2 相同；六條場內線沿 B2 走廊排開（j=0 最靠樓梯側、j=5 最上游），每條線橫越走廊往場側。A 路最靠看台側＝B2 上最靠場側，到 6口 必須對到「以自己的行進方向最先轉進場」的那條線，否則三路在 6口 前左右對調：從樓梯側走向 6口 的（白衣；藍1 在 P1）是 j=0／j=3，所以白 A = 6k−5、藍1 A = 6k−2；藍2–9 從死巷反向走回 6口，先後對調，A 必須是 j=5 = 列 6k，而且死巷的站位偏移要跟著鏡射（3.5）。（修正紀錄：第一版把藍衣全改成 A = 6k−2 來壓掉死巷區頭的交叉，結果藍2–9 三路都在 6口 前交叉——版本 2 的資料也有同樣問題；根因是死巷偏移沒鏡射，不是對應表。）

各列人數取自版本 1 資料 `files[].n`（列 1…54 = 28,29,30,32,34,33,33,32,32,32,31,31,30,29,29,29,29,29,29,29,29,30,31,31,33,34,34,34,33,33,33,33,33,33,33,33,33,33,33,33,33,31,30,28,27,26,25,24,23,22,21,20,19,18）。三路合計 A 534、B 537、C 538。列 13–21 與部分列的排號不從 1 起算，一律以版本 1 `persons` 的實際排號為準。

### 3.4 出口內的座位

每個出口是一條 FIFO。把該出口供應的所有人依**樓梯序號**（3.5 節）排序後，由上排往下填（排號由該區最大排往 1 排），每排由出口側往中央填：

| 區 | 由哪一端開始 |
|---|---|
| 139 | 該排最大號 → 6 號（北端在大號側） |
| 140、141、142、143、145 | 1 號 → 最大號 |
| 144 | 最大號 → 最小號（北端在大號側） |

跳過 blocked/work 席與 139 的 1–5 號。空位只會出現在每個出口的最底排尾端。

欄內的樓梯順序：往 FIFO 集結區（P1、樓梯、P6、以及白4 以後）的欄，排大的先；往 B2 死巷（P2–P5）的藍衣欄，排 1 先。這與版本 2 的 `pai_order` 相同，也決定 6口 順序「排大的先進列」。

### 3.5 集結與候隊

- 白1 → P1（與藍1 同區，六列並排，頭朝 6口）。
- 白2 → 樓梯（`STAIR_SLOTS`，頭在樓梯下，33 格/路，白2 三欄 33/32/32 剛好）。
- 白3 → P6（B1 走廊，頭朝樓梯）。區頭 12.75、間距 0.058（區頭不侵入樓梯區保留的 12.85–13.15；隊尾 u 11.07 − 0.1 ≥ 140 的接入點 u 10.96，白4–7 的 A 路要從那裡接進來）。P6 的站位偏移就是各路自己的偏移（+0.12 / 0 / −0.12），各路就地停下。

### 3.6 時間模型

常數沿用版本 2：步速 V = 1.1 單位/秒；同一路相鄰兩人節拍 HEADWAY = 0.4 秒（走廊、樓梯、6口 皆同）；三路錯開 LANE_STAGGER = 0.17 秒；同排相鄰兩人離座最少 0.28 秒；第一人離座 T0 = 6.73 秒；站定後至少 0.6 秒才起步。

兩個連續時鐘，都是「拉式」倒推，群內（同一區塊／同一大隊）不斷拍，**群與群的交界各路對齊**：下一群在所有路同時起拍，起拍時刻 = 各路上一群最後一拍（含錯開量）的最大值 + 0.4（6口 再加 0.8 秒大隊空檔）。對齊是必要的：各欄人數差 1–6 人，不對齊時較短的路會提早帶下一群出來，在集結區頭與場內轉入點穿過上一群還在走的人（建造時實測 150 對碰撞，全部來自這裡與下一段的接入幾何）。較短的路因此在交界有 ≤ 4.5 秒的空檔，這是欄長不等的必然，不是斷拍。

1. **樓梯時鐘（集結階段）**：路 L 在區塊 b 的第 n 位通過樓梯口的時刻 S = T_b + 0.4·n + 0.17·(A=0, B=1, C=2)，T_b 依上段對齊。離座時刻 = S − 座位到樓梯口路程/V。T_S0 取讓最早離座者剛好在 T0 離座的最小值。站定時刻 = 沿路線走到格位的時刻（格位在樓梯口之前者，提前停下）。適用藍9…白3。
2. **6口 時鐘（進場階段）**：6口 第 j 路在大隊 k 的第 n 位（欄內排大的先）通過 6口 的時刻 G = T_k + 0.4·n + 0.17·j，T_k 依上段對齊並加 0.8 秒空檔（外側路到各列轉入點的路程比內側短約 0.5 單位，前一大隊隊尾要先過）。站定者的起步時刻 = G − 格位到 6口 路程/V，且 ≥ 站定 + 0.6；白4 以後的離座時刻 = G − 座位到 6口 路程/V。T_G0 = 滿足所有人的最小值。兩個時鐘可以重疊：不等集結階段全部站定，大隊 1 在藍1、白1 隊頭站定後就出發，樓梯同時不停、白2 以後接續下樓。（修正紀錄 10/20：初版另要求 T_G0 不早於集結階段最後一人站定 + 1.0，結果大隊 1–3 進場的 41 秒裡樓梯全空，白3 與白4 之間空 36 秒；拿掉這條後全長 290.6 → 260.5 秒，碰撞與檢核照舊全綠。樓梯落點 u≈1.0、西一入口 u≈4.2、死巷 u≥5，三股人流不互穿。）
3. 6口 之後沿版本 1 的場內路徑等速重新計時。

碰撞：全程以 `collide.py`（版本 2 同一套：取樣 0.01 秒、半徑 0.03）驗收，兩項都必須是 0。若有碰撞，處理手段依序只有三種，座位與路別一律不動：

1. 提早離座、在走道口停等（只動座位→走道口這一段，樓梯口與 6口 時刻不變）。
2. 把那個人整條時間線前後平移，幅度 ≤ 0.15 秒（小於半個節拍，所以同一路的先後順序不會變）。
3. 以上都解不掉：停下來回報，不出貨。

因為第 2 種會讓個別拍距偏離 0.4，3.7 的「不斷拍」檢核以 0.4 ± 0.15 為門檻，並同時檢查樓梯口與 6口 的通過順序與計畫序號一致。

## 5. `data.json` 結構

```
meta      title, built, population, tEnd, speedUnitPerSec, mPerUnit, frame,
          headway, laneStagger, t0, tStairStart, tGateStart,
          rules[]（本設計 3.1–3.6 的白話版，給頁面顯示）, assumptions[], checks{}（3.7）
phases    [{key,label,t0,t1}]：seated 就座 / descend 藍9→白3 下樓與候隊 / hold 等待進場 / enter 大隊 1→9 進場
nodes     沿用 base，P2–P5 標籤 藍 2·3…、P6 白 3、STAIR_TOP 樓梯(B1)，各含 X,Y,label,floor,dadui
map       沿用 base
restSeats 沿用 base，who = 位置編碼或 null
exits[]   key, sec, side, stairLabel, entry[x,y], entryU, rank, capacity, used,
          rows[{pai, seats[no…], ids[…]}]（由上排往下）,
          segments[{lane, fromBlock, toBlock, n, firstId, lastId, fromRow, toRow, tFirstLeave, tLastLeave}],
          order[ids]（FIFO）
lanes     {A|B|C: {total, segments[{exit, fromBlock, toBlock, n, fromIdx, toIdx}]}}
groups[]  18 區塊：key(藍9…白9), costume, dadui, population, columns[3], assembly,
          lanes{A|B|C:{lie, exit, n}}, tStairFirst, tStairLast, tGateFirst, tGateLast, tAssembly
files[]   54 列：lie, dadui, costume, n, lane, exit, assembly, order[ids 依 6口 順序],
          tLeave, tAssembly, tEnter, tGate, tArrive
persons[] id, lie, pai, dadui, costume, a, field{X,Y}, rest{sec,pai,no,X,Y},
          exit, exitSeq, lane, laneIdx, gateLane, gateIdx, assembly,
          t{leave, assembly, enter, gate, arrive}, path[[x,y,t]…]
others[]  沿用 base
```

`persons[].t` 與 `path` 的語意與版本 2 相同（頁面的 seated/walk/wait/enter/done 狀態機靠它）。白4 以後 `assembly == enter`。另加 `stairSlots`（白2 的樓梯格位座標，{j:[[x,y]…]}）與 `zones`（P1–P6 的區頭、間距、floor、kind），讓 `check.py` 只靠 `data.json` 就能檢「白2 全員在格位內、白3 隊尾位置」。時間顯示一律 mm:ss（2a 的 `fmt` 是百分比，要換回版本 2 的秒數格式）。

## 7. 建置流程（`build/README.md` 要寫的）

```
python3 plan.py  base.json plan.json             # 3.1–3.4，確定性，秒級
python3 build.py base.json plan.json ../data.json ../seats.csv   # 3.5–3.6，含碰撞處理，數分鐘
python3 check.py ../data.json                    # 3.7，非 0 即 exit 1
```

`plan.json` 不進 git（`.gitignore`）。`check.py` 的結果同時由 `build.py` 寫入 `meta.checks`，`check.py` 重算一次核對一致。

## 8. 留給建造者的事

- `plan.py` 內可以保留一個小的巢狀驗證（3.3 的性質），但指派本身寫死，不做搜尋。
- 白3 的區頭與間距（3.5 的約束內）。
- 碰撞處理的具體做法（版本 2 的走道口停等、提早離座、二分收斂皆可）。
- 各頁的細部版面，但不得改變第 6 節列的內容與互動。
- `meta.rules` 與 `assumptions` 的措辭。
- 總覽頁的檢核例子要顯示到什麼粒度（至少：項目、數字、前三個例子）。

## 9. 假設與風險

- 139 的 1–5 號不可用是沿用現況的假設；若可用，鬆度由 58 席變 107 席，不影響指派。
- 走廊接入點與走道口座標來自版本 1 的示意幾何，不是量測值。
- B2 藍1 與白1 在 P1 並排、以及 藍k 出發穿過 P(k+1)…P5 前的走廊，是版本 2 已通過碰撞檢查的幾何；2c 的時刻不同，若 `collide.py` 在這裡報錯而個人時刻調整解不掉，停下來回報，不要改幾何。
- 白2 樓梯格位沿用版本 1 的 6白 格位，共 33 格/路；白2 三欄 33/32/32。
